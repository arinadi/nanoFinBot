# 08.1 - Save a draft as an immutable transaction

## Behavior

> "User can save a draft as an immutable transaction."

## Increment

Sending a text or photo produces a draft message with Save/Edit/Cancel buttons, and
pressing Save writes a `active` transaction that cannot be edited.

## Depends on

02, 03, 05, 06, 07

## Requirements

- A bot handler routes incoming text and photo to parser/OCR (05/06/07), creates a
  `status=draft` row, and replies with the draft summary and an inline keyboard
  `Save / Edit / Cancel`.
- Pressing Save sets the row to `active` and confirms to the user.
- A `active` row has no edit path (amount/currency/description/type fixed).

## Data and API

- Entities: Transaction (`draft` → `active` via `set_status` from 02).
- Callback data: `save:<draft_id>`, `edit:<draft_id>`, `cancel:<draft_id>`.

## Technical notes

- Persist the draft before showing buttons so an on-demand restart can resume it
  (risk chain 4); the queue resume is 10, but the `draft` row must already exist here.
- Draft fields can be edited only while `status=draft`.
