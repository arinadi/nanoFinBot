# 08.2 - Edit a draft before saving

## Behavior

> "User can edit a draft before saving."

## Increment

Pressing Edit lets the user change the draft's fields and re-presents the draft with
Save/Edit/Cancel.

## Depends on

08.1

## Requirements

- Pressing Edit on a draft puts the bot into an edit state for that `draft_id`.
- The user's next message (text) re-parses the amount/description/type and updates the
  draft row; the updated draft is re-shown with the buttons.
- Editing is possible only while `status=draft`.

## Data and API

- Uses `parse()` from 05 and the draft row update path (only valid pre-save).

## Technical notes

- Simplest edit: treat the follow-up message as a full re-entry parsed by 05, replacing
  the draft's fields. Do not try to do field-by-field editing in this increment.
- Track the in-edit `draft_id` per user (a small in-memory map is fine; on-demand restarts
  may drop it — acceptable, the draft row itself persists).

## Acceptance checks

- [ ] Pressing Edit then sending a new text updates the draft fields and re-shows buttons
      Command: `python -m pytest tests/test_capture.py::test_edit -q`
- [ ] Editing a non-draft (`active`) transaction is refused
      Command: `python -m pytest tests/test_capture.py::test_edit_active_refused -q`

## Out of scope for this nanotask

- Cancel behavior — 08.3.
- Editing a saved (active) transaction — by design impossible (09 is disable-only).
